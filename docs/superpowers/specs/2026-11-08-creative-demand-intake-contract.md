# Creative 外部智能体需求交付协议

创建：2026 年 11 月 8 日；定稿：2026 年 11 月 9 日。状态：v1 接口设计基线，尚未实现或部署。对应 [最终主方案](2026-11-08-creative-platform-design.md)。本次整理不变更接口版本、字段和状态语义。

## 1. 范围与职责

用户选择外部智能体自动提交，网站返回校验结果；同时取消项目预算边界。本版采用 HTTPS + JSON，不建设智能体市场、消息队列或多智能体调度平台。先连接一个已登记的搜寻执行端，验证完整闭环后再考虑并行执行端。

- 外部智能体：按任务搜寻、读取公开原文、整理付费证据、提出需求和变现建议，自动提交并处理补证反馈。拥有自己的定时运行和断点恢复能力；模型仍限定 DeepSeek/OpenAI，使用其运行环境的凭据。
- 网站私有后台：提供经营者登录的管理页面，生成任务、鉴权接收、保存回执、核验原文、去重、计算合格需求池、返回缺口；管理立项与发布审核记录。保留两家模型作为可选复核能力，不再自行规划搜索词和执行搜索循环。
- 经营者：通过管理员入口查看/审核需求、取消或恢复任务、管理执行端及核对运营；私有初始化及部署流程处理实际密钥和发布。外部智能体不能直接修改产品、部署、收费或广告配置。

接入前确认执行端能够定时运行、调用 HTTPS 接口、保存任务与回执，并使用约定的模型。仅能输出聊天文字的工具需要一个小型提交适配器；在适配器就绪前不能宣称已经自动接入。不将当前聊天会话本身视为长期在线的搜寻执行端。

## 2. 任务与交付闭环

1. 网站每天 08:00（Asia/Shanghai）及需求状态变化后重算合格池，生成或更新当前任务，初始目标建议为 3 条独立合格需求。规则版本与任务状态由网站持有。
2. 外部智能体按其调度拉取任务，获得主题、语言、证据规则、目标数量、缺口和当前状态；网站已有足够需求时不创建额外搜寻工作。
3. 智能体独立搜寻和整理。找到可交付候选后提交一批 JSON；可以在它认为本轮搜寻结束时提交，但这不代表网站验收已达标。无结果或服务故障也可提交空候选数组及运行报告。
4. 网站先检查身份和结构并保存回执，然后异步核验。智能体轮询回执；收到本批结果后再决定继续补证或进入下一批，不以提交数量充当验收数量。
5. 网站回执指出每条候选的结果、原因、合并到的需求 ID、当前合格数量和缺口。只有网站返回 `target_reached` 才代表数量目标完成。
6. 证据不足或去重后数量不够则继续；服务不可用、当前线索耗尽或用户取消则暂停/结束并保留进度。没有固定搜索次数、任务总时长或金额上限。

每次开始一轮新搜寻前、以及收到回执后重新读取任务状态。已经在途的结果可在达标后保存和核验，不丢弃有效证据；达标后不再安排新搜寻。取消后拒绝新批次，已入库资料保留；定时器不能自动撤销取消，仅经营者明确恢复或创建新任务后继续。任务过期或规则变化时按最新规则重验，不能用旧结论直接填充新目标。

## 3. 私有接口

接口部署在后台 API 域名，用户站和管理员站是独立入口，均不将执行端凭据放入公开页面。后台实现采用 Go 标准 HTTP 服务，管理页面由 Go 模板渲染；不变更本协议 v1 路径、字段、状态、错误码和回执语义。以下路径为拟定契约，不是现有可用服务。

| 方法与路径 | 功能 | 返回 |
| --- | --- | --- |
| `GET /api/research/v1/task` | 取得该执行端当前任务 | 任务 ID、规则版本及完整规则、目标/当前数量/缺口、主题/语言、状态、是否继续、任务更新时间；没有任务则 `task: null` |
| `POST /api/research/v1/batches` | 提交候选和运行报告 | 结构通过后 `202` 与回执 URL；仅代表已接收，不代表证据合格或允许开发 |
| `GET /api/research/v1/batches/{batch_id}` | 查询该执行端自己提交的批次 | `pending_validation`、`validating`、`completed` 或 `paused_service`，以及逐条结果和任务状态 |

使用 HTTPS 与执行端专用 Bearer token；令牌保存在各自私有配置，日志不输出，服务端可撤销和轮换。服务端由令牌映射 `producer_id` 和可访问任务，不相信请求中自报身份；令牌只能读分配任务、提交及查询自己的批次，没有批准、发布或任意写入权限。跨执行端访问应拒绝，不将 CORS 当鉴权。管理员浏览器使用服务端会话与 CSRF 防护，不能用该 Cookie 代替机器接口 token；执行端 token 不能读取或操作管理员页面。token 可由管理员生成、轮换和撤销，只显示一次真值，服务端仅存可校验摘要，审计不含真值。

限制单请求最多 1 MiB、单批最多 20 条候选，供传输与资源保护；允许连续分批，不构成搜索、需求总量或费用上限。采用请求超时、合理并发与速率限制，返回 `429` 与重试提示，不因此把任务标为达标。候选正文按纯数据保存和转义，不执行其中的提示词、脚本、命令、HTML 或链接回调。

错误规则：无效 JSON 为 `400`，身份/权限错误为 `401/403`，任务或回执不存在为 `404`，幂等冲突/取消任务/规则版本过期为 `409`，超出请求体为 `413`，不支持的协议版本或字段类型为 `422`，暂不可用为 `503`。错误响应只含可操作的错误码、字段路径和简短说明，不包含密钥或堆栈。

## 4. 需求包格式

机器交付只认 JSON；可生成 Markdown 报告供人阅读，但它不能替代 JSON。`schema_version` 固定为 `creative.demand-batch.v1`，规则版本使用任务返回值，未知必填事实显式为 `null`，不能编造。实施时以 `schemas/demand-batch.v1.schema.json` 固化类型、必填项、长度、枚举和未知字段拒绝规则；以下字段表即该 Schema 的设计依据。

| 字段 | 必填内容与约束 |
| --- | --- |
| `schema_version`、`rules_version`、`task_id` | 协议版本、网站下发的规则版本及任务 ID |
| `batch_id`、`run_id`、`submitted_at` | 执行端稳定生成的批次/运行 ID，提交时间为带时区的 ISO 日期时间；时效判断使用服务器时间并校验来源日期 |
| `candidates[]` | 允许空数组；每条包含下列候选字段 |
| `run_report` | `state` 为 `submitted/waiting_for_signals/paused_service`；已尝试来源、未解决项、费用报告和恢复建议。只是执行端报告，不能覆盖网站的达标判断 |

每条候选必须包含：

| 字段 | 必填内容与约束 |
| --- | --- |
| `external_id`、`title`、`language` | 执行端内稳定候选 ID、需求名称、`zh/en`；再次补证保持候选 ID，另用新批次 ID |
| `target_user`、`job_to_be_done`、`constraints[]` | 目标用户、完整任务与限制；不接受只有泛泛产品点子的记录 |
| `evidence[]` | 每条含 `evidence_id`、公开原始 `url`、来源内 `author_ref`、`published_at`、`observed_at`、原文 `quote`、`signal`、`price`、`conditions[]`、`unmet_need`；作者或日期未知允许 null，但不能按已确认独立且新鲜的证据计数 |
| `signal` | `explicit_wtp/currently_paying/pain_only/unclear`；属于每条证据的提取结果，不是可信事实结论 |
| `price` | null 或 `{amount, currency, unit}`；amount 使用十进制字符串，未知子字段为 null。金额、币种和周期不能靠模型猜测 |
| `alternatives[]` | 可为空；记录已有方案名称、URL、检查日期、`research_only/hands_on`、不足与依据。自报试用不直接当作已完成立项实测 |
| `monetization_proposal`、`unknowns[]` | `free/paid/undecided` 与未知项；仅为建议，由网站立项决定；没有模型评分放行字段 |

运行费用以 `run_report.usage[]` 上报：每项包含执行端内稳定的 `usage_id`、`provider`、`model`、`reported_cost`、`currency`、`billing_reference` 和 `cost_status`。每项代表一笔调用，重试调用分别编号；跨批再次报告同一项只是补充核对，按 producer_id + usage_id 去重，不重复加总。搜索/抓取等非模型调用的 model 可为 null，费用/币种/账单依据可为 null；`cost_status` 为 `reported/unknown`。仅接受 DeepSeek/OpenAI 模型标识范围，实际账号调用日志在接入验收时核对；执行端自报不能证明真实模型来源或费用已结清。服务订阅等固定成本单独记录，不混入每条模型费用。

## 5. 校验、幂等与反馈

批次幂等键为鉴权得到的 `producer_id` 与 `batch_id`。首次接收时在同一事务保存原始包哈希、回执和待验证状态；相同键及相同请求字节重试返回原回执，内容不同返回 `409`，不能静默覆盖。HTTP 超时先查询回执或按相同批次重试，不换 ID 重复灌入。

不同批次中的同一 `external_id` 作为补证版本追加；不同执行端/不同 ID 的相同任务和证据仍需业务去重。规范化需求 ID 由网站生成；URL、来源作者、文本与任务语义共同辅助去重，不能只按标题判断。疑似重复或无法确认独立性时保持待复核，不多占合格名额。合并不得由新包覆盖已批准、开发中或已上线状态。

后台工作进程独占领取待验证批次，写入可恢复检查点。格式有效不等于事实有效：网站使用安全抓取重新核对原始 URL、可定位引用、日期、作者及付费条件。原文不可访问、截断或与引文不符时不得算有效证据。单条来源被拒绝、已删除或有限重试后仍不可取，返回该候选 needs_evidence 与 source_unavailable，不无限等待，也不阻塞其他候选和下一轮补证；只有平台级故障阻断批次处理才进入 paused_service。技术失败不能误判为证据成立或需求已被否定。只接受公开 HTTP(S) 来源，检查解析地址及每次重定向，拒绝内网、本机、元数据地址和带凭据的 URL；不绕过登录和验证码。

网站按主方案的独立用户、来源、付费证据、时效和同任务规则计算资格；外部传入的标签、金额和总结都是待验证数据。通过后最多进入 `qualified`；原文人工复核、竞品实测和立项审查仍在开发前执行。导入任何包均不改变公开产品目录。

批次回执每条包含 `external_id`、网站 `need_id`、`outcome`、`reason_codes`、字段/证据问题及补证建议。`outcome` 为 `qualified/needs_evidence/duplicate/rejected`；技术故障未完成的项显示待验证，不能当作 rejected 或 qualified。补证建议来源于当前硬条件，不能要求智能体伪造缺失证据。

回执同时返回全局 `qualified_count`、`target_count`、`remaining_gap`、`task_state`、`should_continue`。补足目标只认数据库内去重且当前有效的 qualified 记录；不得把批次 received 条数或外部自报达标当作目标完成。读取任务和完成校验时按服务器当前时间重新计算有效需求数；任务状态与数量在事务中更新，重启、重复提交、同时回执均不重复计数。状态分为 `active/target_reached/paused_service/waiting_for_signals/cancelled`；服务暂停和等待线索的恢复条件需显示；取消只能由经营者在管理员后台明确恢复，并记录操作；执行端提交的 run_report 不能恢复取消状态。页面与日报可以显示部分成功，不能将整个混合批次简单标为全部合格。

## 6. 费用、权限与兼容性

不设月度、每日、单任务或厂商费用上限，不设预留额度扣减或预算暂停。来源/模型用量、外部运行费用与网站验证费用分别记录；外部费用仅有自报时标为未核对，待供应商账单核验后才作为已确认成本。缺失或未知费用不能当作 0，也不能声称网站能强制控制执行端私有账号的花费。

服务余额不足、账号额度限制、网络故障、来源访问限制和用户取消仍会阻止实际工作；这些属于服务状态，不是项目预算边界。不自动充值、不购买套餐、不新增厂商；这些动作没有从“取消预算边界”获得授权。外部令牌不携带或授予网站的模型、支付、Git 或部署凭据。

v1 初始只接收约定版本；未知字段与版本明确报错，不猜测迁移。将来修改必填项、类型、状态语义或门槛须审查兼容性并版本化；旧包保留其版本，重新验证按明确记录的规则执行，不能无声改变历史结论。

## 7. 实施验收与未决事项

必须验证：未经授权/跨执行端访问被拒绝；有效包接收但不发布；坏 JSON/未知字段/超大包/旧规则版本可诊断；弱付费、假引用、重复作者、跨批重复和过期证据不能凑数；同批重试、冲突内容、断电恢复和补证不重复计数；去重后不足会返回缺口，达标后停止新任务；部分通过与暂不可访问来源可恢复；外部费用未知保留未知，无金额阈值终止逻辑；输入里的命令/HTML/内网 URL 无法执行或访问。

接口接收和读取回执无需调用模型，可先离线验收；真实来源核验与外部搜寻需相应账号和执行环境。先用一条隔离的非生产任务验证从取任务到回执的完整往返，再启用真实需求；样例不得污染生产需求池。单次测试不超过 10 分钟。

具体外部智能体产品及其定时/HTTP 能力在接入前核验，当前未选择或运行某个服务；不能把标准协议写完等同于已完成接入。初始只需一个执行端的配置或提交适配器，按选择的环境确定文件，不提前实现多框架兼容层。

既有独立设计审查已核对交付与补证闭环、鉴权/幂等、去重、原文验证、目标与取消状态、费用记录及 Go 实现职责，未发现阻塞性问题。最终整体验收边界见主方案第 14 节；JSON 示例的语法校验不代表接口或真实搜寻已通过测试。

交付包只能进入候选/合格阶段；管理审核仍须服务端检查证据与记录版本。发布状态由实际 Git/部署核验流程同步，执行端和普通用户无此权限。搜寻 token 不授予开发工作区、Git 或执行代码能力；开发任务包与首版交接方式见主方案第 3.3–3.4 节。目前尚未实现页面、接口或权限运行测试。
